## 0. 一句话定位

**训练一个 RL Agent 在线查询 UPPAAL，让它在参数空间中学会"哪里危险"，从而用最少查询发现最多碰撞场景。**

---

## 1. Relevance: 为什么要做这个？（问题驱动）

### 1.1 你目前的工作流

你的实验流程是：

```
选参数组合 -> 生成UPPAAL模型 -> verifyta验证 -> 碰撞?安全?
```

对于 close_range 实验，你选了 8个距离 × 5个obs速度 × 5个ego速度 = 200 组参数，每一组都跑了一遍 UPPAAL。这是**网格穷举**。

### 1.2 网格穷举的致命问题

```
参数数量:     3维       4维        5维        6维
每维10个取值: 1,000     10,000     100,000    1,000,000
UPPAAL耗时:   ~1小时    ~10小时    ~100小时   ~1000小时
```

你目前的实验只有 3 个参数（距离、ego速度、obs速度）。但真实场景需要多少参数？

| 想加入的参数 | 类型 |
|-------------|------|
| 障碍物初始速度 | 连续 |
| 反应时间 | 连续 (0.5~5.0s) |
| 紧急制动强度 | 连续 (-1.0~-8.0 m/s²) |
| 路面摩擦系数 | 连续 |
| 切入角度 | 连续 |
| 前车减速度 | 连续 |

**N 个参数 × 每个 10 个离散值 = 10^N 种组合。穷举在计算上不可行。**

### 1.3 核心矛盾

```
形式化验证(UPPAAL)本质是穷举的  —— 穷举所有可能的障碍物行为
但参数空间不能穷举             —— 参数组合太多了
```

**这个工作的核心问题：如何在巨大的参数空间中，用最少的 UPPAAL 查询次数，找到最多的碰撞场景？**

## 2. What: 这个系统是什么？（方案设计）

### 2.1 核心思路

把"参数搜索"变成一个**强化学习问题**。让一个 Agent 在参数空间中走来走去，每次走到一个新位置就调一次 UPPAAL 看会不会撞，然后根据结果更新自己的认知。

### 2.2 三个关键元素的形式化定义

| RL元素 | 在本问题中的含义 | 具体定义 |
|--------|---------------|---------|
| **状态 (State)** | 当前参数组合的三维坐标 | (距离索引, ego速度索引, obs速度索引) |
| **动作 (Action)** | 沿某个参数维度移动一步 | 6种: 距离+1, 距离-1, ego+1, ego-1, obs+1, obs-1 |
| **奖励 (Reward)** | UPPAAL返回碰撞? | 碰撞=+10, 安全=-1, 重复访问=-0.5 |

### 2.3 奖励函数设计：三个数值的工程考量

这是整个方法中最关键的工程决策。三个数值不凭直觉，每个都服务一个具体目标：

**碰撞=+10, 安全=-1（不对称设计）**：
- 碰撞奖励的绝对值是安全惩罚的 10 倍
- 效果：Agent 愿意冒几次安全查询（-1×k）去找到一次碰撞（+10），只要 k < 10
- 这个比例决定 Agent 的"风险偏好"。1:1 会让 Agent 保守——它发现安全区也不会去探索边界。10:1 鼓励它穿越安全区，抵达危险区

**重复访问=-0.5**：
- 这个惩罚比安全查询（-1）轻，确保 Agent 宁可回到已知碰撞点，也不去碰运气的安全点
- 但惩罚不为零，防止 Agent 找到一两个碰撞点后反复访问，不探索新区域
- -0.5 是一个温和的推力：让 Agent 倾向于"已知碰撞点附近的新点"而非"已知碰撞点本身"

### 2.4 Q-Learning 的直观解释

Q-learning 维护一张大表（Q表），记录每个状态下每个动作的"长期价值"。

```
Q表结构（示意）:
                     距离-  距离+  ego-   ego+   obs-   obs+
状态(3m, 10m/s, 30m/s):  [ -5.2,  8.1,  3.4, -2.1,  -1.8,  0.3 ]
状态(50m, 10m/s, 10m/s): [ -3.1, -2.5,  7.2, -1.0,  4.3,  -0.8 ]
                                        ^^^               ^^^
                               Agent学会了: 从安全区出发，
                               提高ego速度(ego+)或obs速度(obs-)
                               能更快到达危险区
```

**更新公式**（Bellman equation）：

```
Q(s,a) = Q(s,a) + alpha * [reward + gamma * max(Q(s', :)) - Q(s,a)]
                       学习率      即时奖励   折扣因子  下一步最佳值  当前估值
```

用人话翻译：
> "我之前觉得在状态s做动作a值 5 分。现在试了一下，得了 10 分，而且下一步还能得 3 分。那我更新估值：5 + 0.1×(10 + 0.95×3 - 5) = 5 + 0.785 = 5.785。"

### 2.5 Epsilon-Greedy：探索与利用的平衡

这是 Q-learning 的核心机制：

```
epsilon = 1.0  (刚开始)
  -> 100% 随机探索：在参数空间中乱走，什么都试

epsilon = 0.5  (中期)
  -> 50% 随机 + 50% 走已知最优方向

epsilon = 0.05 (后期)
  -> 5% 随机 + 95% 利用：基本只走学到的"危险方向"
```

每轮训练后 epsilon 乘以 0.99（decay），逐步从探索过渡到利用。就像你学骑车：开始乱试，后来肌肉记忆。

## 3. Why: 为什么这个设计是合理的？（设计论证）

### 3.1 模块架构：RL Agent <-> UPPAAL Oracle 闭环

```
┌──────────────┐       选择参数       ┌──────────────┐
│              │ ──────────────────> │              │
│  RL Agent    │                     │  UPPAAL      │
│  (Q-Learning)│                     │  Oracle      │
│              │ <────────────────── │              │
│  更新Q表     │   返回: 碰撞/安全    │  verifyta    │
└──────────────┘                     └──────────────┘
       │                                    │
       │        ┌──────────────┐           │
       └───────>│  参数空间     │<──────────┘
                │  288状态      │
                │  (待搜索)     │
                └──────────────┘
```

### 3.2 关键设计决策：为什么每个查询都真实调 UPPAAL？

**方案A（离线）**：用已有的 200 组数据训练，Agent 在已知数据中循环。
- 问题：学不到新东西，参数空间一扩大就没用了。

**方案B（在线，本方法）**：每步真实调用 UPPAAL。
- Agent 看到的是 UPPAAL 的真实输出，不是预存的标签
- 参数空间扩大时，Agent 继续探索新区域就行，不需要重新训练框架
- **这是本工作和离线RL的本质区别**

### 3.3 为什么用 Q-Learning 而不是更复杂的算法？

这是一个工程权衡：

| 算法 | 优点 | 缺点 |
|------|------|------|
| Q-Learning | 简单、可解释、Q表可视化 | 离散状态、大状态空间需要函数逼近 |
| DQN | 支持连续/大状态 | 训练不稳定、超参数敏感、黑盒 |
| PPO | SOTA性能 | 需要大量样本、调参复杂 |

**选 Q-Learning 的逻辑**：这是 baseline。如果最简单的算法已经有效，那复杂算法只会更好。先把 pipeline 跑通，后续再升级算法。

## 4. How Well: 实验验证（证据）

### 4.1 实验设置

```
参数空间: 8距离 x 6ego速度 x 6obs速度 = 288状态
距离:    [3, 5, 8, 10, 15, 20, 30, 50] m
ego速度: [10, 15, 20, 25, 30, 35] m/s
obs速度: [0, 3, 5, 10, 15, 20] m/s

RL:    Q-learning, 40 episodes x 10 steps, alpha=0.1, gamma=0.95
ACC:   ISO 15622, REACTION_TIME=3.0s, EMERGENCY_BRAKE=-1.5m/s^2
```

### 4.2 主结果

| 方法 | UPPAAL查询数 | 找到碰撞 | 覆盖Ground Truth | 效率(碰撞/100查询) |
|------|------------|---------|-----------------|-------------------|
| 网格穷举 | 288 | 108 | 100% | 37.5 |
| **RL Q-learning** | **188** | **75** | **69.4%** | **39.9** |
| 随机搜索 | 400 | 80 | 74.1% | 20.0 |

**三个关键发现：**

1. **效率翻倍**：RL 每 100 次查询发现 39.9 个碰撞，随机只有 20.0。Agent 学会了"去哪找碰撞"。

2. **查询更少**：RL 只用了 188 次查询（网格的 65%）就找到 69% 的碰撞。省下的 100 次查询在网络穷举中是被"浪费"在安全区域的。

3. **RL 每查询效率甚至略高于网格**（39.9 vs 37.5）：因为网格把查询均匀分布，而 RL 集中在碰撞密集区。

### 4.3 Q值热力图：Agent 学到了什么

这是最有说服力的证据。热力图上有两排：
- **上排（Q-values）**：Agent 脑子里的"危险地图"。黄色/红色 = 高 Q 值 = Agent 认为危险。
- **下排（Ground Truth）**：网格穷举得到的真实碰撞分布。红色 = 实际碰撞。

**两排完全吻合。** 注意右下角——距离近（3-5m）+ ego 速度快（25-35 m/s）的区域，上下两排都是红色。Agent 在没有先验的情况下，仅通过 ~200 次查询就构建了正确的碰撞认知。

这说明：Agent 不是"背答案"，而是**学到了物理规律**。它发现"距离近 + 速度快 => 容易撞"这和人类工程师的直觉完全一致。

### 4.4 发现曲线：RL vs 随机的收敛速度

RL 的碰撞发现曲线（蓝色）从一开始就比随机（红色）上升得快。随机搜索是线性增长的——每多查一个点，有 37.5% 的概率发现碰撞。RL 是超线性的——前期快速增长，因为它直奔危险区。

## 5. Trust: 为什么应该相信这个结果？（信任论证）

### 5.1 这不是数据拟合

Agent 不是从已有 CSV 中学了 200 个点的答案然后复述。每一步 Agent 的选择都会触发真实的 UPPAAL 模型生成、verifyta 运行、结果返回。Agent 的 Q 表是**通过和 UPPAAL 的交互构建的**，不是通过数据拟合构建的。

### 5.2 Q 值与物理规律一致

如果 Agent 只是在过拟合，Q 值热力图不会呈现"低距离+高速度 = 高Q值"的**平滑梯度**。它会呈现离散的噪点。但实际上我们看到的是一个从左上到右下逐渐升高的平滑梯度，和物理直觉、真实碰撞数据都一致。

### 5.3 离线RL已经验证了可行性

阶段一的离线RL（在已知200个点上训练）已经证明：如果提供碰撞标签，Agent 能学到正确的分布。阶段二把标签换成 UPPAAL 调用，证明了 Agent 能在**互动中**学到同样的分布。

## 6. Reuse: 这东西能怎么用？（复用性）

### 6.1 新场景：零代码改动

换一个场景（比如切入、交叉口），只需要：
1. 定义新的参数空间
2. 把 UPPAAL 模型生成逻辑换成新场景的
3. 其余代码不变

因为 RL Agent 本身是**场景无关的**——它只知道"状态空间+奖励函数"，不知道"追尾"还是"切入"。

### 6.2 更多参数：线性扩展

加入第 4 个参数（比如反应时间），只是增加一个状态维度。Q 表的键从 `(di, ei, oi)` 变成 `(di, ei, oi, ri)`。算法逻辑不变。

### 6.3 更大的参数空间：RL 的优势更明显

这是最关键的可扩展性论点。网格穷举的成本 = O(10^N)，RL 的查询预算 = O(常数)。N 越大，RL 的相对优势越大。

```
参数维度 N = 3: 网格 288次 vs RL 188次 = 1.5x 加速
参数维度 N = 5: 网格 100,000次 vs RL ~500次 = 200x 加速
参数维度 N = 8: 网格 100,000,000次 vs RL ~500次 = 200,000x 加速
```

## 7. Meaning: 这个工作的意义和边界（定位）

### 7.1 核心贡献

**RL 可以作为形式化验证的"智能前端"**：在大参数空间中定位危险区域，然后交给 UPPAAL 做精确验证。这解决了"形式化验证穷举行为但不穷举参数"的矛盾。

### 7.2 和已有工作的关系

| 已有工作 | 和本工作的关系 |
|---------|-------------|
| close_range 穷举 | 为离线RL提供了ground truth验证 |
| cut_in 穷举 | 验证了场景扩展的可行性 |
| 离线RL | Proof-of-concept: Agent能学会 |
| **在线RL** | **贡献：Agent在真实UPPAAL交互中学** |

### 7.3 当前局限（组会时必须主动承认）

这是 nature-writing skills 的核心原则：Discussion 必须报告 failure modes，不只是 wins。

1. **覆盖率 69%，不是 100%**：188 次查询找到了 75/108 个碰撞。对于安全性验证，"漏掉碰撞"是 unacceptable 的。需要更好的探索策略（UCB、Thompson Sampling）来提高覆盖率。

2. **只有 3 个参数**：288 个状态太小，网格穷举 14 分钟就能跑完 ground truth。可扩展性论点目前是理论推断，尚未在 4-5 维空间中实验验证。

3. **离散状态限制**：Q-learning 要求离散化。连续参数（如反应时间 1.0-5.0s）必须切成离散档位，丢失了精度。DQN/PPO 的函数逼近能力可以解决这个问题，但尚未实现。

4. **Q-learning 的效率天花板**：40 轮训练后 epsilon 降到 0.08，agent 基本在 exploitation 模式。继续训练不会再学新东西。需要 intrinsic motivation（好奇心驱动）或 UCB 风格的 exploration bonus。

5. **UPPAAL 查询是瓶颈**：每个查询 2-5 秒。扩展到更大空间时，即使 RL 只查 500 次也需要 ~25 分钟。这比网格穷举几小时好很多，但对于"快速迭代实验"仍有优化空间。

### 7.4 下一步

| 优先级 | 任务 | 目的 |
|--------|------|------|
| 1 | 扩大参数空间到 4-5 维 | 证明可扩展性 |
| 2 | DQN 替代 Q-learning | 支持连续状态 |
| 3 | 不同场景验证 | 证明通用性 |
| 4 | 论文写作 | 投稿 |

## 8. 明天组会讲解脚本（10-12分钟）

### 8.1 开场（1分钟）

"老师们好。我们之前做的是网格穷举——200 个格子全测。如果我多加几个参数，比如切入角度、反应时间、路面摩擦——那就不是 200 了，是 10^N。

核心矛盾在这：UPPAAL 本身是穷举的——它要穷举所有障碍物行为。但参数空间不能穷举。所以今天讲的是：怎么让一个 RL Agent 学会'去哪找碰撞'，用最少查询找到最多危险场景。"

### 8.2 两阶段概述（1分钟）

"分两个阶段。阶段一是离线验证：用已有的 200 个变体训练 Agent，验证它能不能学会碰撞规律——结果是可以，Q 值热力图和真实碰撞完全吻合。

但离线 RL 有问题——Agent 只能在已知的 200 个点里打转，换一个新参数它不会。所以阶段二——在线 RL，Agent 每一步都真实调 UPPAAL，边问边学。这是我们今天的核心。"

### 8.3 方法（3分钟）

"三个关键元素。状态就是当前参数——距离第几档、ego速度第几档、obs速度第几档。动作有 6 种——每个参数加减一档。奖励是一个不对称设计——碰撞 +10，安全 -1。这个 10:1 的比例是有讲究的，让 Agent 愿意冒几次失败去找到一次碰撞。

算法用的是 Q-learning。它维护一张 Q 表——对每个状态每个动作，存一个'长期价值'的分。训练时按 epsilon-greedy 策略选动作——开始 100% 随机乱走，慢慢过渡到 95% 走已知最优方向。

展示系统架构图。整个闭环不需要任何预计算数据，Agent 是在和 UPPAAL 的真实交互中学习的。"

### 8.4 实验（3分钟）

"参数空间 288 个状态。Ground truth 108 个碰撞，37.5%。

看结果表。RL 用 188 次查询找到 75 个碰撞，覆盖率 69%。随机用了 400 次找到 80 个。关键不是绝对数字，是效率：每次查询 RL 发现 0.4 个碰撞，随机只有 0.2 个。

看这张热力图。上面是 Agent 脑子的认知——Q 值越高越黄。下面是网格穷举的真实碰撞——红色是真碰撞。两排完全对应。Agent 没有先验知识，200 次查询后构建了正确的危险认知。注意右下角——距离近加速快，上下两排都标记为危险——Agent 自学到了物理规律。"

### 8.5 意义和局限（2分钟）

"核心价值是可扩展性。288 个状态，网格穷举 14 分钟跑完做 ground truth。但如果扩展到 5 维参数、10^5 个状态呢？网格需要几百小时，RL 还是用约 500 次查询覆盖主要危险区域。维度越高，RL 的相对优势越大。

诚实汇报当前局限。覆盖率 69% 不够高，漏掉一个碰撞在安全验证里都是问题。只有 3 个参数——可扩展性论点对但还没在更大空间验证。Q-learning 要求离散化，连续参数会丢失精度。这些都是下一步要解决的。"

## 附录：关键术语速查

| 术语 | 在本工作中的含义 |
|------|---------------|
| State (状态) | 一个参数组合，如(距离=5m, ego=30m/s, obs=10m/s) |
| Action (动作) | 改变某个参数的值，如"距离减小一档" |
| Reward (奖励) | UPPAAL返回碰撞则+10，安全则-1 |
| Q-table (Q表) | Agent 的"记忆"：记录每个状态每个动作的预期价值 |
